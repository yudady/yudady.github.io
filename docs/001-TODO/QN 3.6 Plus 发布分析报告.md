## 一、模型概述

QN（通义千问）于 **2026年4月20日** 发布了新旗舰模型 **QN 3.6 Plus**。该模型的核心定位是 **Agentic Coding（智能体编码）**、**实用推理** 和 **完成真实工作**，而非仅仅"听起来聪明"。

官方强调，许多模型能够很好地解释事物，但当涉及到实际导航代码库、规划步骤、修复问题、或在整个长任务中保持连贯性时，这些模型往往开始出现困难。QN 3.6 Plus 正是针对这一痛点而设计。

**核心优势方向：**
- 代码编写
- 仓库级（repo-level）任务
- 前端生成
- 输出实用性（而非空话）

---

## 二、关键特性

### 百万级上下文窗口

QN 3.6 Plus 默认配备了 **100万 token 的上下文窗口**。

虽然上下文数字常被用于营销宣传，但如果模型在长上下文中确实能保持实用性，那就是巨大的优势。当项目变大、涉及多个文件、现有模式、测试、文档和边界情况时，许多模型会"迷失方向"。

### 上下文窗口的实际意义

| 场景 | 普通模型表现 | QN 3.6 Plus 预期表现 |
|------|------------|-------------------|
| 小型单文件项目 | 正常 | 正常 |
| 多文件中型项目 | 开始丢失上下文 | 保持稳定 |
| 大型仓库级任务 | 严重退化 | 长会话稳定 |
| 跨文件关联修改 | 困难 | 保持连贯性 |

## 三、使用方式与免费策略

### QN Code（官方终端编码代理）

QN 3.6 Plus 可通过 **QN Code** 免费使用：

1. **安装 QN Code**：QN 的开源编码代理，运行在终端中
2. **选择 Q Oath 认证方式**
3. **使用 QN 账号登录**
4. **开始使用**

QN Code 本身是**开源**的，这使得整体工具包对开发者非常友好。

**免费额度**：目前 QN Code 官方表示，Q Oath 认证流程提供 **每天 1,000 次免费请求**。

**适用人群：**
- 学生
- 独立开发者
- 爱好者
- 想要在付费前充分测试模型的专业人士

### OpenRouter 集成

QN 3.6 Plus 同时也在 **OpenRouter** 上提供免费路由：

- 如果已经在使用 OpenRouter 配合编辑器编码助手或自定义配置，可以直接在该平台试用
- **无需更换现有工作流**即可评估模型
- 可将其接入已使用的工具，快速判断是否适合自己的任务

> ⚠️ 注意：OpenRouter 的免费路由可能有限制、临时可用性变化和速率约束。免费不等于无限量，也不意味着始终完美稳定。

### 使用方式一览

| 使用方式 | 是否免费 | 是否开源 | 门槛 | 适合人群 |
|----------|---------|---------|------|---------|
| QN Code + Q Oath | 每天 1000 次免费 | 工具开源 | 安装→登录→使用 | 终端用户 |
| OpenRouter 免费路由 | 免费（有限制） | — | 接入现有工具链 | 已有 OpenRouter 用户 |

### 免费策略的战略意义

> "如果你的模型确实好用，那就让人们去用它。让他们在真实的代码仓库上测试，让他们与 Claude、Gemini、GPT、Deepseek 等他们已经在用的模型进行对比。信任就是这样建立的。"

## 四、AI 编码工具市场分析

### 当前市场定价乱象

当前 AI 编码工具的定价情况"简直是五花八门"：

| 类型 | 描述 | 典型代表 |
|------|------|---------|
| 工具很好但很贵 | 功能强大，但成本过高 | GitHub Copilot Enterprise |
| 价格便宜但效果一般 | 性价比不高 | 部分开源方案 |
| 模型强但工作流不喜欢 | 被限制在特定工作流中 | Cursor |
| 演示好看但烧积分 | demo 精彩，真实使用消耗大 | 部分新入局者 |

**结论：** 每当有强大的模型出现，且人们可以在不先付费的情况下认真试用时，它自然会变得更有吸引力。

### Agentic Coding 趋势

编码模型正变得越来越 **agentic（智能化）**。这已经不再仅仅是一次性代码补全了：

```
传统编码模型                    Agentic 编码模型
┌──────────┐                   ┌──────────────────┐
│ 单次请求  │                   │ 理解整体目标       │
│ 单次补全  │        →         │ 自主检查结果       │
│ 无法回溯  │                   │ 多步骤规划执行     │
│ 无状态    │                   │ 长任务保持连贯     │
└──────────┘                   └──────────────────┘
```

## 五、开放权重讨论

### 现状

QN 作为一个品牌，在**开放模型**方面建立了很强的声誉。很多人将 QN 与有用的开放版本联系在一起，这些版本可以以更灵活的方式运行。

然而，QN 3.6 Plus 这款旗舰模型**并非开放权重**。

### 影响评估

| 用户类型 | 影响评估 |
|----------|---------|
| 只关心自托管/本地部署的人 | ❌ 缺点：不能自托管 |
| 想要完全控制基础设施的人 | ❌ 缺点：无法自行运行 |
| 想要使用优秀编码模型的人 | ✅ 优势：访问门槛低、免费试用 |
| 对开放权重无强需求的人 | ✅ 优势：实用性强、易于推荐 |

**核心观点：** "闭源但高度可访问"（Closed but highly accessible）

### 阿里巴巴的开源承诺

阿里巴巴已表示，将继续以**对开发者友好的尺寸**支持开源社区的**选定 QN 3.6 模型**。

```
QN 生态模型
├── QN 3.6 Plus（旗舰）  → 闭源 ❌
├── QN 3.6 其他尺寸      → 开源 ✅（开发者友好尺寸）
└── QN Code（工具层）     → 开源 ✅
```

并非完全放弃开放模型，而是旗舰版闭源 + 基础版开源的双轨策略。

## 六、使用门槛对比

低使用门槛的重要性经常被低估：

> "如果设置过程很烦人，大多数人会一直说'以后再试'，然后就再也没有试过。但如果路径基本上是'安装、登录、开始使用'，那么更多人会真正认真尝试。"

```
使用门槛对比
┌─────────────────┐     ┌─────────────────┐
│  高门槛模型       │     │  QN 3.6 Plus    │
│                  │     │                  │
│  注册企业账号     │     │  安装 QN Code    │
│  等待审批        │  →  │  Q Oath 登录     │
│  配置计费        │     │  开始使用        │
│  绑定信用卡      │     │                  │
│  结果：大多数人   │     │  结果：更多人    │
│  从未真正试用     │     │  认真试用        │
└─────────────────┘     └─────────────────┘
```

## 七、总结评价

### 优势

- ✅ **模型实力强** — 聚焦编码和推理，正好是当前需求所在
- ✅ **免费使用** — QN Code 中的免费访问非常实用（1000 次/天）
- ✅ **OpenRouter 可用** — 额外的免费试用渠道，无需换工具
- ✅ **工具层开源** — QN Code 本身是开源的
- ✅ **使用门槛低** — 安装、登录、开始使用，三步搞定

### 注意事项

- ⚠️ **非开放权重** — 旗舰 Plus 版本为闭源，不能自托管
- ⚠️ **OpenRouter 免费路由限制** — 可能有速率约束和可用性变化
- ⚠️ **实际效果待验证** — 基准测试和真实使用可能有差异

### 综合评价

> "QN 在这里做对了很多事情。模型看起来很强。对编码和推理的聚焦正是需求所在。QN Code 中的免费访问非常实用。OpenRouter 的可用性也很好。虽然不是开放权重，但比许多其他旗舰级模型更容易试用。这种组合使它很容易被推荐。作为实际使用的模型，它看起来非常出色。"
