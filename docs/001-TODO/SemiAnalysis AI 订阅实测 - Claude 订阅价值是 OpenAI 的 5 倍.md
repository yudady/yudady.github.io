## 订阅黑盒：进度条背后的隐藏定价

### API 透明 vs 订阅模糊

| 维度 | API 计费 | 订阅制 |
|------|----------|--------|
| 计价单位 | 每百万 token，分输入 / 输出 / 缓存写入 / 缓存读取四类明码标价 | 0-100% 用量进度条（5 小时窗 + 7 天窗） |
| 参照物 | 换算成美元账单，可精确对账 | 「比 Plus 多 20 倍」类宣传语，且 OpenAI 已删除这类表述 |
| 隐藏变量 | 无 | 每个（模型, token 类型）组合消耗不同的内部 credits，比例从不公开 |
| 调价方式 | 公告 + 价格页 | 可静默调整（见下方 A/B 测试实测） |

**为什么删掉「20 倍」宣传语很关键**：倍数是消费者唯一的参照物。参照物消失后，厂商砍额度时你无法量化损失了多少——这是定价透明度的单向退化。

### SemiAnalysis 实测方法论

报告的核心思路：**把进度条当仪表，用受控实验反推每个 token 类型的隐藏单价**。

```
                    SemiAnalysis 限额压力测试流程
 ┌─────────────────────────────────────────────────────────┐
 │  针对每个 (套餐, 模型, token类型) 三元组单独设计实验        │
 └──────────────────────────┬──────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
 ┌─────────────┐    ┌───────────────┐   ┌──────────────┐
 │ 测输入/缓存  │    │  测缓存读取    │   │   测输出      │
 │ 喂《战争与   │    │ 固定标签首次写 │   │ 逼模型写长篇  │
 │ 和平》片段   │    │ 缓存后反复读   │   │ 技术文章      │
 │ 每次换随机   │    │ (500M token   │   │ 一次逼出      │
 │ 标签强制缓存 │    │  不动表=免费)  │   │ ~16K token    │
 │ 完全失效     │    │               │   │               │
 └──────┬──────┘    └───────┬───────┘   └──────┬───────┘
        └───────────────────┼──────────────────┘
                            ▼
              ┌──────────────────────────┐
              │ 盯进度条：每跳一格，记录   │
              │ 期间真实消耗的 token 数    │
              │ → 每格 token 数 = 隐藏单价 │
              └────────────┬─────────────┘
                           ▼
              ┌──────────────────────────┐
              │ 丢弃首尾不完整步进，      │
              │ 持续跑到误差收敛 ±5% 内   │
              └────────────┬─────────────┘
                           ▼
              ┌──────────────────────────┐
              │ 假设 agentic 负载形状，    │
              │ 按 API 价格折算出         │
              │ API 等价价值（美元）       │
              └──────────────────────────┘
```

### 实测插曲：厂商会静默 A/B 你的额度

测试中三个相同订阅账号，其中一个额度比另外两个低约 20%。向厂商核实后对方承认：该账号被分进一个「极其微小的」限额 A/B 测试，并强调「不是 wholesale 降低额度」，而是在测试「如何更好地平衡限额触顶」。

两个结论：

- 厂商**随时可以静默修改**你的订阅额度，不会有公告
- SemiAnalysis 的方法**灵敏到能抓出这类细微调整**——个人用户也可以用类似思路（记录进度条 + token 消耗）自查

## 核心实测结论：$200 套餐的 API 等价价值

### Claude Max 20x 档在不同模型下的价值

同一张 $200/月订阅卡，跑 agentic 负载，按 API 价格折算的月度等价价值：

| 模型 | API 等价价值 | 相对 $200 标价倍数 | 备注 |
|------|-------------|-------------------|------|
| Sonnet 5.5 | $12,529 | 62.6x | 性价比最高 |
| Opus 5.5 | $11,726 | 58.6x | 与 Sonnet 差距很小 |
| Fable 5.1（最新旗舰） | $2,485 | 12.4x | 且被锁 50% 总量上限 |

**同一个套餐，内部差了 5 倍**——订阅价值不由套餐单独决定，而是由**套餐 × 模型 × 负载形状**三元组决定。聊天负载和 agent 连跑 8 小时的消耗结构完全不同，后者 96% 以上是缓存读取（cache read）。

### Claude vs OpenAI 同价位对比

| 档位对比 | Anthropic | OpenAI | 差距 |
|----------|-----------|--------|------|
| 旗舰档（$200） | Fable 5.1 值 $2,485，但只能消耗总额度的 50%，卡里还剩一半 | GPT-6 Astra 值 $2,897，跑完直接见底 | 量级接近，Anthropic 有余量 |
| 中档全线（$20/$100/$200） | Opus 5.5（两家钦定的日常主力） | GPT-6.1 Sol | **全线约 5 倍** |

**「5 倍」的口径要精确理解**：5x 指中档模型（Opus 5.5 vs GPT-6.1 Sol）在 $20/$100/$200 各档的 API 等价价值比值，而非旗舰档对比（旗舰档两家额度接近，差距在于 Anthropic 的 Fable 锁 50% 上限）。视频标题的「差 5 倍」即此口径；开头「值一万二 vs 两千出头」是 Claude 中档与 OpenAI 旗舰的跨模型粗略对比，约数口径。

OpenAI 唯一的反驳点：Pro 全系无 5 小时限额，更容易吃满月度总额度。但 SemiAnalysis 认为这不足以抵消 Opus 5.5 约 4-5 倍的价值差距。即使换成 raw token 数口径（剔除 API 定价失真），报告承认差距仍「massive」——视频引述图表称缩到约 2.5 倍，正文未载该具体数字（见勘误表）。

### OpenAI 阵营的辩护与报告的回应

OpenAI 负责订阅的 Tibo 回应：我们的模型完成任务用的 token 更少，单看 API 等价价值会失真。SemiAnalysis 侧的让步与反驳：

- 承认：API 等价价值算法会放大贵模型的优势，行业也缺乏可靠的 token 效率数据
- 反驳：**额度减半是实测事实，token 效率优势还停留在口头主张——一个可验证，一个不可验证**

## 补贴生意的本质：Anthropic 内部账本

### 订阅业务的真实成本结构

SemiAnalysis 对 Anthropic 的估算（每兆瓦推理算力口径）：

| 业务线 | 收入贡献 | 算力消耗 | 每 MW 收入 | 毛利率 |
|--------|---------|---------|-----------|--------|
| 订阅 | ~10% | **42%** | $16M | ~50% |
| API | ~90% | ~58% | $103M | 92% |
| **综合影响** | — | — | 订阅把每 MW 混合收入拉低约 **$36M** | — |

订阅业务是**厂商贴钱买来的增长**，贴的还是最贵的旗舰模型推理算力。补贴什么时候收、怎么收，取决于财报压力——OpenAI 的订阅收入占比更高，压力更大。

### 毛利率测算：跑满 vs 现实利用率

$200 Claude 套餐的毛利率（假设 API 毛利率 92% 基准）：

| 场景 | 全跑 Opus 5.5 | 全跑 Fable 5.1 |
|------|---------------|----------------|
| 100% 利用率跑满 | **-369%**（每收 $1 倒贴近 $4 算力） | 1%（刚好打平） |
| 20% 现实利用率 | 6% | 80% |

```
        订阅制的底层赌注：用不满的人 补贴用得满的人

  利用率分布（示意）                补贴流向
  ┌──────────────────────┐
  │ ██████ 大多数人 <20%  │ ───┐
  │                      │    │    ┌─────────────────┐
  │                      │    ├──→ │ 高频专业开发者   │
  │                      │    │    │ (最忠诚、产出最高)│
  │ ████ 高频跑满的用户   │ ───┘    └─────────────────┘
  └──────────────────────┘
                                  │
                                  ▼
                    「补贴收缩」最先砍的就是跑满的人
```

这解释了为什么每次砍额度，反弹最激烈的都是重度 agentic 用户——他们恰好是商业模式里被补贴供养、也是被收窄针对的同一批人。

## 两大龙头的应对策略：渐进防御 vs 核选项

### 策略对比

| 维度 | Anthropic：渐进式防御 | OpenAI：核选项（一刀切） |
|------|----------------------|------------------------|
| 做法 | 模型越旗舰，订阅内 API 等价价值压得越低（Sonnet 62.6x → Opus 58.6x → Fable 12.4x）+ 旗舰锁 50% 总量上限 | 不分模型，所有档位一刀切到 Fable 水平（$200 直接腰斩） |
| 体感 | 新旗舰模型「耗得更快」，老模型额度没变 | 什么都没干，下个月额度少一半 |
| 用户参照 | 可继续用中档模型的高性价比 | 失去「买贵档更划算」的惯例 |
| 社区舆情 | 多次计划砍订阅被社区骂回去（报告确认 repeatedly walk back），舆论施压有效 | 靠 DevDay 正面宣传 + 一个月缓冲期 + 补偿 credits 基本躲过反弹 |

### OpenAI 调价时间线（2026-10）

```
2026-10 ────────────────────────────────────────────────────→
  │
  ├─ 调价公布（报告发布前一周，Tibo 宣布）
  │    • $200 档各模型档位 token 数减半
  │    • Sol 级跌超 50%（6.1 Sol 同时下调缓存输入价格）
  │    • 上架 $500 新档：额度仅比旧 $200 多 21%（对 Astra）
  │      → 真实卖点是 300 TPS Ultra-fast 模式（限额仍在测）
  │    • Pro 100/200/500 每美元价值完全一致（扁平化）
  │      → 调整前：Pro 200 每美元 ≈ Plus 的 4 倍（越贵越划算）
  │      → 调整后：买大档更划算的时代结束
  │
  ├─ 老用户缓冲包
  │    • 9/22-9/29 持有有效订阅者：旧额度保留至 10/29
  │    • 新购用户立即执行新额度
  │    • 一次性 62,500 usage credits（官方口径价值 $2,500，年底过期）
  │
  └─ 10/29 大限：老用户高额度到期，新额度全面生效
       （被保护的重度用户将同时撞上真实新额度，社区反应待观察）
```

### 补贴定价的自洽机制：API 降价 ≠ 订阅增值

一个容易被忽略的问题：模型 API 降价时，订阅额度会不会同步调整以保持价值恒定？报告的实测答案：**不会，且两家行为不一致**。

| API 降价事件 | 订阅侧跟进？ | 结果 |
|--------------|-------------|------|
| Fable 5.1 缓存读取 -75%（vs Fable 5） | Fable token 上限完全没加 | 订阅价值被稀释 |
| Opus 5.5 输入输出 -20%、缓存读取 -60% | Opus 上限上调（Max +20%、Pro +50%） | 上调不足以完全抵消降价 |
| GPT 6.1 Sol 缓存读取 -50%（此前 GPT 6 Sol 已比 5.6 Sol 便宜 60-67%） | Sol token 上限没变 | API 等价价值掉约 30% |

结论：订阅额度是**动态政策**，不是固定产品。API 价格表的每次调整都可能静默改变你订阅的真实价值。

## 中国厂商：仍在烧钱换量

报告测了智谱 GLM、月之暗面 Kimi、MiniMax 等中国厂商，方向与 OpenAI 相反：

| 维度 | 中国厂商 | OpenAI（砍后） |
|------|---------|---------------|
| 补贴阶段 | 仍处高补贴烧钱获客期 | 补贴收窄完成 |
| 每美元价值随档位 | 档位越高越划算（递增） | 三档完全一致（扁平化） |
| 平均每美元 API 等价价值 | 略低于 OpenAI 的 ~12x | ~12x |

视频转录引用报告图表的两个点：MiniMax Token Ultra 达 23.4x，智谱 GLM Coding Max 达 11.6x（该具体数字出自报告图表，正文未载，见勘误表）。对国内开发者的含义：一两百块人民币的档位，按 API 折算能拿到千元级的算力。

另一份报告结论：**第三方订阅（Cursor、Cognition/Devin 等 wrapper）劣于第一方订阅**——同样的模型，走自家套餐更值。

### 选型判断决策树

```
开始选订阅
  │
  ├─ 你的负载是 agentic 编程（缓存读取 >96%）？
  │    ├─ 是 → 首选中档模型跑量（Sonnet/Opus 级性价比远超旗舰档）
  │    │       Claude Max 档当前价值最高（全线 5x 口径）
  │    └─ 否（日常对话为主）→ 利用率大概率 <20%，任意家都够用
  │                          别为用不到的额度买大档
  │
  ├─ 需要旗舰模型（Fable/Astra 级）？
  │    ├─ 是 → 注意 Anthropic 旗舰锁 50% 总量上限
  │    │       OpenAI 旗舰额度略高但跑完见底
  │    └─ 否 → 回到中档模型逻辑
  │
  ├─ 在国内、预算人民币一两百档？
  │    └─ 中国厂商仍在高补贴期，档位越高性价比越高
  │       （但补贴收窄是大方向，好价有时效性）
  │
  └─ 任何选择前问一句：我的 prompt 和工具链
     能不能 5 分钟内切到另一家？
      ├─ 能 → 你有议价权，随市场波动换船
      └─ 不能 → 先做迁移性改造，再谈订阅
```

### 最佳实践

- ✅ 每月看一次 usage 面板的缓存读取占比，量化自己的负载形状
- ✅ 日常辅助任务分流到中阶模型，把旗舰额度留给真正需要的场景
- ✅ 把 prompt、自动化脚本、项目结构模块化，保持双厂商可切换
- ✅ 记录自己的「进度条消耗 vs 实际 token」比例，建立个人基准线，厂商静默调额时你能第一时间发现
- ❌ 不要按「X 倍用量」宣传语做购买决策——倍数已被删除或失去参照意义
- ❌ 不要把订阅额度当固定产品写进长期成本预算——它是随时可调的政策快照
- ❌ 不要在单一厂商上沉淀不可迁移的工作流（自定义工具深度绑定、私有 prompt 资产无导出方案）

## 后续观察点

1. **10 月 29 日**：OpenAI 老用户高额度到期，新额度全面生效。被缓冲期保护的重度用户将同时撞上真实额度，社区反应是检验「公关缓冲术」长期效果的关键节点
2. **Ultra-fast 300 TPS 实测**：$500 档的核心卖点限额数据尚未发布，300 TPS 到底配多少量决定该档值不值
3. **Anthropic 下一步**：订阅吃 42% 算力只贡献 10% 收入的结构不可长期维持——要么涨价、要么收额度、要么靠下一代模型把推理成本打下来。视频作者倾向三者组合，补贴收窄是大方向，区别只在姿势
