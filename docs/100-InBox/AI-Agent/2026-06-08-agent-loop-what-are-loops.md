# 别再 prompt AI？搞懂爆紅的 Agent Loop，再决定要不要学

> 📺 [思思主播](https://youtu.be/BQVKqdLuCoM) · 2026-06-08 · Video ID: `BQVKqdLuCoM`
> 原文：tonbi《What Actually ARE Loops? (And Do I Need Them?)》

## TL;DR

AI 圈流行一句话："别再对 AI 下指令了，去打造那个会替你对 AI 下指令的东西。" 但 Loop 不是魔法，而是一套需要严谨逻辑、实体证据、还要有刹车机制的流程。大多数人现在不需要 all-in，但值得搞懂底层逻辑。

---

## 什么是 AI Agent Loop

**不是**程式课里的 for-loop。它是一个**会重复执行、会自己拿工具用、能自我验证成果**的 AI 流程。骨架搭好后，负责对模型下指令的不再是人，而是机器自己。

### 六个步骤

1. **触发** — 叫它起床工作
2. **给上下文** — 背景、目标、约束
3. **给工具** — 可以用的能力
4. **验证** — 做完后检查结果（最关键，最容易被偷懒跳过）
5. **重复决策** — AI 评估要不要再跑一次
6. **停止规则** — 什么时候收手，叫人来帮忙

### 为什么验证是灵魂

> "如果你建了一个流程但少了自我验证，那不配叫 loop，那叫一堆自动燃烧你 token 预算的营火。"

没有验证 = AI 一轮接一轮狂跑，API 费用狂飙，但没人确认事情做对没有 = 定时放火。

## 你需不需要 Loop？两个灵魂拷问

| 问题 | 答案 |
|------|------|
| 这件事会一直重复发生吗？ | ✅ / ❌ |
| AI 自己能判断有没有做对吗？ | ✅ / ❌ |

**两个都"会"才值得建 Loop，否则乖乖用简单 prompt 下指令。**

### 适合 Loop 的例子
- 维护 PR 提案（每天都在发生 + 有明确的 pass/fail 信号）
- 修复时好时坏的测试（系统给明确信号，AI 好验证）

### 不适合 Loop 的例子
- 一次性任务
- 依赖人类主观品味的工作（比如让 AI 判断"这个设计是不是太丑了"）
- 为了一次性且充满主观判断的事搞自动化 = 给自己找麻烦

## 两位顶尖实践者的做法

### Boris Cherny（Claude Code 负责人）— 由上而下：定时排程

- 把 Loop 当成写程式的介面，没有黑魔法
- 底层：Claude 模型 + cron 定时排程 + 记忆功能
- 平常 5-10 个 agent 在背景同时跑
- 可能每几分钟巡一次测试顺便修 bug，每半小时自动整理 Twitter/Slack 回馈

**Robo Bun 范例**（有证据的自我验证）：
1. 有人回报 bug
2. **先重现问题** → 写一个会失败的测试码（证明 bug 真的存在）
3. 证据确凿后 → 动手修程式
4. 修完 → 再跑一次测试确认通过
5. 最后 → 开 PR 送出

每一步都是铁证，这才是让人放心的自动化。

### Peter Steinberger（OpenClaw 作者）— 由下而上：文件规则

- 心理学切入：捕捉"好烦"的那个瞬间 = 你正在做机器人早该自己做的事
- **vision.md**：项目的最高宪法（AI 该做什么、绝不能做什么）
- **agents.md**：让 AI 自己分流 Discord 问题、自己录影证明 bug 修好
- 最狂：**让 Agent 自己改写规则文件**（发现矛盾时自己清理 = AI 帮未来的 AI 写说明书）

**安全设置 — 逃生舱机制**：
> "如果你在关键的地方卡住了，而且连续失败三次，立刻停下来，去叫人类来处理。"

这条强制拔插头规则 = 防止死胡同烧光 token。

## 务实建议

**先别焦虑，先从小实验开始：**
1. 学习 → 做个小实验
2. 亲手验证结果
3. 调整设计 → 执行
4. 回顾检讨

确认这个流程顺畅后，**再把验证慢慢放手交给 AI**。慢慢来比一上来就全面自动化有效率得多。

### 核心判断框架

```
需要 Loop？
├── 任务重复发生？
│   ├── 否 → 用普通 prompt
│   └── 是 ↓
└── AI 能自我验证？
    ├── 否 → 用普通 prompt
    └── 是 → 值得建 Loop
```
