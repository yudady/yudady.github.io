## 核心洞察：持久 > 聪明

```
❌ 我们一直在问的问题              ✅ 应该问的问题
─────────────────────────────────────────────
下一个 AI 还能变多聪明？           它能不能 24/7 不下线？
跑分又提升了多少？                 它能不能记住上次的上下文？
这个模型的 IQ 有多高？             它能不能自己排程工作流？
```

```
2024 年的竞争范式              2026 年的竞争范式
─────────────────────────────────────────────
拼模型智商                      拼持久运行
拼单次对话质量                  拼端到端工作流
拼谁能付得起 API 费            拼谁能把系统跑得够便宜
一个天才型实习生                一个永远在背景运作的幽灵员工
```

**判断轴的校准**：

```
從：                          到：
「AI 變聰明了」       ──→      「AI 變持久了」
「更強的模型」        ──→      「更長駐的系統」
「一次性任務」        ──→      「24/7 自主運行」
「聊天工具」          ──→      「基礎設施」
```

## 聊天机器人的错觉

我们大多数人对 AI 的想象，还停留在「超级聪明的实习生」阶段：

```
聊天機器人模式                     持久化系統模式
─────────────────────────────────────────────
你丢 prompt → 它回答              你设置目标 → 它持续执行
单次交互                           长期自主运行
没有记忆（每次从零开始）           有记忆（跨会话上下文）
被动等待指令                       主动观察环境并触发
一个工具                           一套系统架构
```

关键转折：从 **「AI 是工具」** 到 **「AI 是基础设施」**。

│           AI 持久化的七大支柱              │

│     持續改進自己的表現                   │

## Zero Human Company — 零人类公司

276 个案例中最极端的实践，社群有人用 **"Zero Human Company"** 来形容自己的架构：

```
Zero Human Company 運作模式

┌──────────┐    ┌──────────┐    ┌──────────┐
│ Agent A  │    │ Agent B  │    │ Agent C  │
│ 寫代碼   │───→│ PR Review│───→│ 抓 Bug   │
└──────────┘    └──────────┘    └────┬─────┘
                                      │
                                      ▼
                              ┌──────────────┐
                              │半夜自動部署    │
                              │ (Auto Deploy) │
                              └──────────────┘
```

**更极端的案例**：有人弄了两家「对打」的 AI 公司，用不同的成长指标让它们互相竞争测试。

**个人助理层面的情感冲击**：有用户把 AI 深度整合进 Gmail、Telegram、Discord 等 15 种环境，24 小时观察并自动打点一切，发出了「这个 AI agent 真的会融化我的心」的评价。

**全自动化影片管线**：从抓网络趋势 → 主题研究 → 写脚本 → 生成影片素材 → 最终发布，完全不需要人类介入。

## 成本战线：真正的革命所在

**核心论点**：如果 276 个超酷的工作流跑起来要倾家荡产，那一点意义都没有。

```
2024 年                              2026 年
─────────────────────────────────────────────
拼谁能付得起 API 费                  拼谁能把系统跑得够便宜
GPT-4 API 贵得要命                   便宜模型 + 本地推理
套壳生意                             基礎設施生意
有能力用 = 競爭優勢                 跑得便宜 + 穩定 = 競爭優勢
```

竞争公式：

```
競爭優勢 = 功能 × (24/7 在線) ÷ 成本

成本是分母 —— 成本越低，優勢越大
持久是乘數 —— 24/7 比偶尔用強 10 倍以上
```

## 五大成本压榨大绝招

社群实践者的五种降低成本的方法：

| 方法 | 说明 | 效果 |
|------|------|------|
| **跑本地模型** | 用 Llama、Qwen 等开源模型替代 API | API 费 → 0（硬件成本） |
| **旧手机当服务器** | 淘汰的 Android 手机跑长驻 Agent | 硬件成本 ≈ $0 |
| **廉价 VPS** | 月费十几美金的云端主机 | 远低于主流云服务 |
| **云端路由** | 简单任务分发便宜模型，复杂任务用强模型 | 按需分配，省钱 |
| **自建推理层** | 优化过的推理层榨干硬件效能 | 极致性能/成本比 |

### 成本优化决策树

```
你的任務複雜度？
│
├─ 簡單（分類/總結/格式化）
│   └─ 本地小模型（Qwen2.5-3B / Llama-8B）
│       成本 ≈ $0/月
│
├─ 中等（多步推理/工具調用）
│   └─ 廉價 VPS + 中型模型
│       成本 ≈ $10-20/月
│
├─ 複雜（代碼生成/多 Agent 協作）
│   └─ 本地強模型 + 關鍵步驟用 API
│       成本 ≈ $20-50/月
│
└─ 極致省錢
    └─ 舊 Android 手機集群 + 本地推理
        成本 ≈ $0/月（電費而已）
```

> 这意味着学生、一人创业者、周末创客，都有能力绕过天价云端账单，自己养一套 24/7 不下线的 AI 系统。

## 评估 AI 的新框架

下次有人吹某个新 AI 模型多革命性时，先问三个问题：

| # | 问题 | 考察维度 |
|---|------|---------|
| 1 | 它能不能记住你们上次聊过什么？ | **记忆持久性** |
| 2 | 它能不能自己排程下一次什么时候该行动？ | **自主调度能力** |
| 3 | 它能不能在你睡觉的时候自己把整条工作流跑完？ | **端到端自主性** |

```
三個問題的答案趨勢：

全是「不能」  →  還是聊天工具
一個「能」    →  初級自動化
兩個「能」    →  正在變成基礎設施
三個「能」    →  AI 已經是基礎設施了
```

## Paperclip：Zero Human Company 的开源实现

> ⚠️ 原始 X 讨论中提到的 ZHC 实验主要使用 **Paperclip** —— 一个开源的 Node.js 服务器，用于编排 AI Agent 组成零人类公司。

| 属性 | 详情 |
|------|------|
| 定位 | 开源 AI Agent 编排框架 |
| 技术栈 | Node.js + React |
| 功能 | 组织图、角色、预算、治理 |
| 支持 Agent | Claude Code、Codex、OpenClaw 等 |
| 用途 | 跑 Zero Human Company 的控制平面 |

### ZHC 实验中的典型架构

```
┌─────────────────────────────────────┐
│           Paperclip 控制平面         │
│    （組織圖 / 角色 / 預算 / 治理）   │
├─────┬─────┬─────┬─────┬────────────┤
│ CEO │ CTO │ Eng │ Mkt │ Finance    │
│Agent│Agent│Agent│Agent│   Agent    │
└──┬──┴──┬──┴──┬──┴──┬──┴─────┬──────┘
   │     │     │     │        │
   └─────┴─────┴─────┴────────┘
            自主協作
         24/7 不下線運行
```

Brian Roemmele 的 ZHC 实验中有 100+ 个 Agent 并行运行，使用 JouleWork 能源支持货币进行内部经济协调。

## 总结

```
核心信息（一句話）：

典範轉移不是 AI 變聰明了，而是 AI 變持久了。
競爭壁壘不是誰的模型更強，而是誰能把系統跑得更便宜、更穩定、更 24/7。

行動建議：
1. 停止追趕下一個「更聰明」的聊天機器人
2. 解決成本支線 → 選便宜模型或雲端方案
3. 打造一個 24 小時不下線的自動化工作流
4. 評估 AI 時問：更持久了嗎？而不是更聰明了嗎？
```
